# SPHERE-PPL Wheat Crop Disease Forecasting -- reproducibility environment.
#
# Versions are pinned to what the results in analysis/ were actually produced with,
# so the panel reproduces the submitted numbers rather than whatever resolves today.
# Developed and run on Python 3.13.13.
#
#   python -m venv venv && source venv/bin/activate
#   pip install -r requirements.txt
#
# REPRODUCE THE FORECAST. analysis/ is numbered in dependency order -- run from the
# repo ROOT (every path inside is repo-relative), in this order:
#
#   python analysis/s02_fetch_weather.py --parse-only  # -> growing_season_weather.csv
#   python analysis/s03_thermal_wetness_splash.py      # -> thermal_wetness_splash.csv
#   python analysis/s04_growth_stage.py                # -> growth_stage.csv
#   python analysis/s07_features_and_model.py          # test scores + feature importances
#   python analysis/s09_final_forecast.py              # -> submission/*.csv  <-- THE FORECAST
#
# s01_season_reference, s05_fungicide_decay, s06_spatial_spread and s08_rolling_origin
# are imported by the steps above rather than run directly.
#
# analysis/evidence/ holds the analyses that justify the design (which learner, which
# routing, which features mattered). None is needed to produce the forecast:
#   python analysis/evidence/model_comparison.py       # XGBoost vs LightGBM/CatBoost/GLM
#   python analysis/evidence/shrinkage_calibration.py  # yellow rust smoother selection
#   python analysis/evidence/shap_analysis.py          # feature attribution + figures
#
# NOTE ON THE WEATHER CACHE: analysis/weather_raw/ holds the raw Open-Meteo daily
# JSON, so every step above runs OFFLINE and is exactly reproducible. Only
# s02_fetch_weather.py WITHOUT --parse-only calls the network, and it
# skips any region already cached. Source: Open-Meteo Historical Weather API
# (ERA5/ERA5-Land reanalysis), free and key-free.
